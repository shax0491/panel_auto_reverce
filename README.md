# Auto‑server switching  — автопереключение сервера при падении

Отдельный проект от основной панели и базового репозитория AntiZapret — здесь
собирается механизм, который переключает клиента на резервный VPN-сервер
"на лету", когда основной сервер недоступен, без ручных действий пользователя.

Причина отдельного репозитория: это принципиально другой класс задачи (клиентские
устройства/роутеры, а не сама панель), и трогать основные репозитории здесь не нужно.

## Почему это не тривиально

WireGuard/AmneziaWG/OpenVPN — протоколы без встроенного failover. В отличие от
Xray/sing-box (то, чем управляют Clash/3x-ui), где "авто-группа серверов" —
штатная фича самого протокольного ядра, у WireGuard-семейства один туннель =
один статичный сервер. Автопереключение приходится строить СНАРУЖИ протокола:
кто-то должен следить за живостью текущего сервера и сам, физически,
активировать другой профиль/интерфейс.

**Важное ограничение с самого начала:** ICMP ping на сами VPN-сервера отключен
в конфиге (защита от сканирования/DDoS) — значит, health-check не может быть
банальным "пропинговать IP сервера". Используются два надёжных способа вместо
этого:
- **На роутере**: ping публичного надёжного адреса (например 1.1.1.1) *через*
  поднятый туннель — если сервер жив и реально форвардит трафик, такой пинг
  проходит; если сервер лёг, туннель поднят на уровне интерфейса, но трафик не
  идёт, и это обнаруживается.
- **На Android**: свежесть последнего WireGuard/AmneziaWG хендшейка
  (handshake) — та же логика, что уже используется в самой панели для
  определения "онлайн"/"оффлайн" клиента (см. `native_awg2_runtime.py` в
  AdminPanelAZ_new), только тут наоборот — клиент следит за сервером.

## Архитектура по платформам

### Роутеры (OpenWrt) — см. `router/`
Полностью реализуемо на стандартных, проверенных временем средствах OpenWrt:
несколько интерфейсов AmneziaWG (по одному на сервер) + `mwan3`
(multi-WAN manager, штатный пакет для ровно такого класса задач — обычно
используется для переключения между двумя провайдерами интернета, здесь
применяется к "провайдерам VPN"). `mwan3` сам следит за здоровьем через ping
сквозь интерфейс и переключает маршрут по умолчанию — ничего из этого не
нужно изобретать заново.

### Android — см. `android/`
Официальный клиент проекта — "AmneziaWG" (`amnezia-vpn/amneziawg-android`) —
**больше не поддерживается разработчиком и не имеет никакого API для внешнего
управления** (ни Tasker, ни broadcast-интентов, ничего). Вместо него
предлагается **WG Tunnel** (`wgtunnel/android`, независимый форк-преемник):
активно поддерживается, официально поддерживает AmneziaWG 2.0–3.1
(Jc/Jmin/Jmax из коробки), и — ключевое — имеет
intent-based automation API, которым можно командовать извне
(`SET_TUNNEL_UP`/`SET_TUNNEL_DOWN` с именем туннеля). Сам он не умеет
health-based failover между несколькими серверами "из коробки" — это и есть
то, что должен делать компаньон-watcher из этого репозитория.

**Это значит смену рекомендуемого клиента для Android-пользователей** (с
"AmneziaWG" на "WG Tunnel") — стоит иметь это в виду при обновлении
инструкций в основной панели/README, когда фича будет готова.

## Статус

- [x] Router/OpenWrt: генератор конфигов + failover через mwan3 — черновая
  реализация есть, физического роутера под рукой не было, синтаксис
  проверен, живое тестирование — на вашей стороне.
- [x] `router/linux-watchdog/`: портируемый watchdog для обычного Linux-шлюза
  (не OpenWrt) — проверен на реальном сервере AntiZapret. Обнаружение
  недоступности и переключение подтверждено; подтвердить, что новый сервер
  после переключения отвечает, с этой же машины не удалось (у неё нет
  hairpin NAT — не баг кода, см. `router/linux-watchdog/live-test.sh`).
- [x] Панель (ветка `feature/failover-pool` в AdminPanelAZ_new): пулы
  серверов + синхронизация peer'ов между узлами + токен-эндпоинты для
  устройств (`/public/failover/{token}/config`, `/status`) — готово,
  покрыто тестами (backend+frontend), живьём на реальных PL2/LV1 ещё не
  гонялось. `linux-watchdog/fetch-config.sh` (новое) забирает готовые
  конфиги с панели по токену, `failover-watchdog.sh` умеет опционально
  слать туда статус (`PANEL_API_BASE`/`PANEL_DEVICE_TOKEN`) — см.
  `router/linux-watchdog/README.md`.
- [x] Android watcher-приложение (AZ AutoSwitch) — собран и прогнан на
  эмуляторе (Android Studio + SDK, Pixel 6/Android 15): UI, разрешения,
  foreground-сервис и health-check-цикл работают live. Настоящий WG Tunnel
  (GitHub Releases) поставлен рядом — его package/receiver/action совпали
  один в один с зашитыми в `WgTunnelController.kt`, broadcast доставляется
  без ошибок. Не проверено: физическое устройство, настоящее переключение
  туннеля (требует настройки Remote Control в самом WG Tunnel — уже
  пользовательский шаг). Подробности — `android/README.md`.
