# AZ AutoSwitch (Android)

Компаньон-приложение, которое следит за живостью текущего VPN-сервера и
командует **WG Tunnel** переключиться на резервный, когда основной падает.

## Почему WG Tunnel, а не официальный клиент "AmneziaWG"

Официальный Android-клиент проекта (`amnezia-vpn/amneziawg-android`,
рекомендован в README базового репозитория AntiZapret) **больше не
поддерживается и не имеет вообще никакого API для внешнего управления** —
ни Tasker, ни broadcast-интентов, ничего. Автопереключение на нём в принципе
невозможно без переписывания самого клиента.

[WG Tunnel](https://github.com/wgtunnel/android) — независимый активно
поддерживаемый преемник: полная поддержка AmneziaWG 2.0–3.1 (Jc/Jmin/Jmax
из коробки, то есть совместим с профилями, которые уже генерирует панель),
и, главное — рабочий `RemoteControlReceiver` с командами
`START_TUNNEL`/`STOP_TUNNEL`/`TOGGLE_TUNNEL` по broadcast-интенту.

**Значит, пользователям Android для автопереключения нужно ставить WG
Tunnel вместо AmneziaWG.** Оба поддерживают AmneziaWG-профили одинаково — это
просто более живой форк того же по сути клиента.

## Как это работает

1. В WG Tunnel импортируются профили всех серверов (обычным способом — как
   раньше импортировали в AmneziaWG), туннели называются осмысленно
   (`srv1`, `srv2`, ...).
2. В WG Tunnel: Settings → Remote Control → включить, задать ключ (любая
   строка — общий секрет между WG Tunnel и этим приложением, защита от
   команд от посторонних приложений).
3. В AZ AutoSwitch: вписать те же имена туннелей (по приоритету, первый —
   основной), тот же ключ, и запустить.
4. Дальше сервис в фоне раз в N секунд стучится на публичный надёжный адрес
   (по умолчанию `generate_204` от Google) — **не на сам VPN-сервер** (на
   него ICMP и вообще прямые обращения из конфига намеренно отключены).
   Как только активен туннель WG Tunnel, весь трафик приложения (в том
   числе эта проверка) идёт через него — так что это честная проверка "жив
   ли сервер и реально ли пропускает трафик", а не просто "поднят ли
   интерфейс".
5. Если подряд `downThreshold` проверок (по умолчанию 3, то есть ~45 сек
   при интервале 15 сек) не прошли — шлём WG Tunnel'у команду поднять
   следующий по приоритету туннель. Дальше это уже забота WG Tunnel —
   переподключение неизбежно (это ограничение самого протокола, не
   реализации), но происходит без участия пользователя.

## Собрать и запустить

**На этой машине нет Android SDK/JDK/Gradle** — код написан и структурно
корректен (стандартные, хорошо задокументированные Android/Kotlin
паттерны), но не скомпилирован и не запущен ни разу. Собрать можно так:

1. Открыть папку `android/` в Android Studio (Ladybug или новее) — она сама
   подтянет Gradle wrapper, JDK и всё остальное при первом открытии проекта.
2. Дать Android Studio один раз обновить версии AGP/Kotlin/Gradle, если
   предложит (я закладывал актуальные на момент написания, но конкретные
   патч-версии могли выйти новее).
3. Собрать и поставить на телефон (Run ▶ или `Build > Build APK(s)`).

## Известные ограничения этой первой версии

- Не тестировалось на реальном устройстве — ни сборка, ни рантайм.
- Точные action/extra-строки `RemoteControlReceiver` взяты из исходников WG
  Tunnel на GitHub (`core/broadcast/RemoteControlReceiver.kt`,
  `util/Constants.kt`) на момент написания — если разработчик поменяет
  название пакета/API, `WgTunnelController.kt` — первое место для правки.
- Health-check по HTTP предполагает, что WG Tunnel маршрутизирует ВЕСЬ
  трафик устройства через себя по умолчанию (стандартное поведение
  Android VpnService) — если в WG Tunnel включено разделение трафика
  (per-app tunneling) и это приложение туда не попадает, проверка будет
  идти мимо туннеля и работать некорректно. Держите AZ AutoSwitch вне
  список split-tunneling в WG Tunnel (или не используйте split-tunneling
  вовсе).
- Иконка — временная системная (`ic_menu_compass`), под замену.
- Нет UI-полировки — это рабочий скелет, не финальный дизайн.
