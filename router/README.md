# Автопереключение сервера на роутере (OpenWrt)

## Идея

Каждый VPN-сервер — отдельный интерфейс AmneziaWG на роутере
(`awg_srv1`, `awg_srv2`, ...). `mwan3` (штатный пакет OpenWrt для
мульти-WAN) следит, какой из них реально работает, и переключает
маршрут по умолчанию на следующий по приоритету, если текущий "упал".

Health-check — пинг публичного адреса (по умолчанию 1.1.1.1) **сквозь**
конкретный туннель, а не самого VPN-сервера (ICMP на сервера отключен
намеренно). Если сервер жив — пинг проходит через его интерфейс; если лёг —
интерфейс формально поднят, но пакеты никуда не доходят, mwan3 это видит и
переключает.

## Файлы

- `servers.example.json` — манифест серверов (ключи, обфускация, приоритет).
  Скопируйте в `servers.json` и заполните реальными данными (можно взять из
  уже скачанного `*-am2.conf` профиля клиента — там все нужные поля).
- `lib/gen-uci-network.sh` — генерирует секции `/etc/config/network`
  (по интерфейсу AmneziaWG на сервер).
- `lib/gen-mwan3-config.sh` — генерирует секции `/etc/config/mwan3`
  (health-check + приоритет + правило маршрутизации).
- `install.sh` — ставит пакеты, гоняет генераторы, импортирует в uci,
  применяет.

## Как использовать

1. На роутере (или на этой стороне и скопировать) заполнить `servers.json`
   по образцу `servers.example.json` — по одному блоку на сервер, `priority`
   меньше = приоритетнее (1 — основной).
2. Скопировать на роутер и запустить:
   ```sh
   scp servers.json lib/gen-uci-network.sh lib/gen-mwan3-config.sh install.sh root@<router-ip>:/tmp/
   ssh root@<router-ip> 'cd /tmp && sh install.sh servers.json'
   ```
3. Проверить: `mwan3 status`, `mwan3 interfaces`, `logread -f | grep mwan3`.

## Честно про ограничения этой версии

- **Не тестировалось на реальном роутере** — под рукой не было устройства.
  Синтаксис shell-скриптов проверен (`bash -n`), но реальный прогон через
  `jshn`/`uci`/`mwan3` — только на вашей стороне при первом запуске.
- **Имена опций `luci-proto-amneziawg`** (`awg_jc`, `awg_jmin`, ...) взяты по
  аналогии с задокументированным поведением awg-openwrt на момент написания.
  Разные форки пакета (`amnezia-vpn/amneziawg-openwrt` vs сторонние сборки
  под конкретные архитектуры) могут называть их чуть иначе — если
  `network reload` не поднимет интерфейс, сверьте с
  `/lib/netifd/proto/amneziawg.sh` на самом роутере.
- **Архитектура пакета**: `kmod-amneziawg`/`amneziawg-tools` собираются под
  конкретный процессор/версию ядра OpenWrt — `install.sh` печатает
  архитектуру роутера, но сама установка зависит от того, есть ли готовый
  `.ipk` под неё в используемом источнике пакетов.
- Переключение при этом подходе — это смена маршрута по умолчанию на уровне
  роутера, то есть **все устройства за роутером переключаются одновременно**,
  без каких-либо действий на самих устройствах (телефон/ПК просто продолжают
  ходить через тот же роутер).
